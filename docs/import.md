# Документы и таблицы по запросу

Обычный запуск, чтение готового кейса, DOCX и XLSX работают на стандартном Python3.10+. Для **нового PDF** нужен pypdf6.21.4 из `requirements-import.txt`; проверка выполнена в отдельном окружении с этой версией. Без него команда выдаёт понятный отказ до изменения состояния. Ничего не устанавливается автоматически.

```sh
python tools/agent.py ingest projects/my-product brief.docx --id D1 --source-type own_material --allowed-material
python tools/agent.py excerpt projects/my-product --source D1
python tools/agent.py excerpt projects/my-product --source D1 --unit 2 --offset 0 --length 2000
python tools/agent.py source-read projects/my-product --source D1 --unit 2 --note "Прочитан абзац с ограничениями; согласование не подтверждено"
```

`--allowed-material` — декларация оператора: открытый или собственный материал без персональных/закрытых данных. Для `public_documentation` нужен `--url https://...`; команда **не посещает URL** и не подтверждает лицензию/публичность. Сначала проверяет это человек/модель по доступному источнику. Произвольные вложения не включаются в конкурсную поставку; упаковщик разрешает только три авторских оригинала учебного intake-case.

Импорт сохраняет неизменяемый снимок `original.ext`, `index.json` с извлечёнными единицами и `note.md` с происхождением/ограничениями. SHA вычислен по тем же байтам, которые читал парсер. `indexed` означает только извлечение; активный проверенный вывод не может опираться на непрочитанный импорт. `source-read` фиксирует реально прочитанный диапазон, краткую цитату и hash полного диапазона, статус `read_excerpt`. Эта декларация не доказывает истинность документа. В стратегии связывайте каждый вывод с ID и конкретным местом; при частичном чтении не заявляйте, что проверили весь файл.

## Точные места и границы

| Формат | Локатор | Что не установлено автоматически |
|---|---|---|
| PDF | Страница с1; диапазон символов сохранённого текста | Вёрстка, графика, таблицы как структуры, сканы/OCR. Пустая страница получает явное предупреждение |
| DOCX | `word/document.xml/w:document/w:body/w:p[N]` или путь таблица/строка/ячейка/абзац | Номера страниц Word, рисунки, исправления; заголовки/колонтитулы/сноски перечислены как пропущенные. Номер XML-ячейки при объединении не равен визуальному столбцу |
| XLSX | Реальное имя листа и адрес ячейки, включая пробелы между заполненными ячейками | Пересчёт формул, актуальность кэша, трактовка дат/единиц по стилям, диаграммы и скрытие. Сохраняются формула, тип и кэш отдельно |

Числовой `<v/>` у формулы означает отсутствие пригодного результата; `0`, `FALSE` и сохранённая пустая строка различаются. Ни одна формула/макрос/внешняя связь не исполняется. Команды внутри текста остаются недоверенными данными.

Пределы по умолчанию: оригинал32MiB; ZIP≤2000частей/64MiB распакованных данных, с проверкой фактического чтения; ≤2000единиц/100000символов текста, локатор≤512символов; PDF≤40страниц. В pypdf ограничены распаковка потока8MiB и работа декодирования32MiB; дочерний процесс прерывается через30с. Это ограничения парсера и времени, **не абсолютная изоляция памяти**. При пределе файл отклоняется или частичность явно записывается. Не увеличивайте пределы ради прохождения тяжёлого файла: выберите разрешённый фрагмент или текстовый экспорт.

Обзор `excerpt`≤2000символов, выбранный фрагмент≤6000 вместе с заголовком; следующий диапазон выбирается отдельно. `status` выводит всё состояние и такого лимита не имеет. Парсер вызывается один раз на импорт, затем читается сохранённый индекс с проверкой hash оригинала/индекса/заметки. `status`, `briefing`, `init` не загружают парсеры и не вызывают сеть/модель. Не запускайте приёмку и помощников на каждом простом вопросе.

## Новая версия и сбой

Не заменяйте импортированный оригинал поверх старого: сохраните прежние файлы, вызовите `stale --claim D1 --reason ...`, импортируйте новый разрешённый файл под новым ID, перечитайте и перенесите основания с явной историей. Старый источник/его hash сохраняются. Новая индексация сама не пересматривает решение человека.

Записи выполняет один процесс. После аварии между файлами остаётся `import.pending.json`, новые записи и checkpoint блокируются. `python tools/agent.py recover-import projects/my-product` откатывает только локальные state/register и новый каталог импорта к снимкам до операции; журнал сохраняет событие отката. Если в каталоге появились неожиданные файлы, сначала ручная сверка. Внешних действий импорт не выполняет. Ошибки до маркера не меняют граф/реестр; снимки временного извлечения удаляются.

## Проверено

`tools/check_import.py`:8 тестов, включая источник/кэш/локаторы/пределы/rollback; в базовом Python PDF пропущен, в окружении pypdf6.21.4 все8прошли. `intake_walkthrough.py` проверяет новый кейс и stale в копии. `efficiency_check.py` хранит20пар обычных запусков против релиза4; протокол зафиксирован до измерения. Это технические результаты, не измерение бизнес-КПД.

Основу DOCX-локаторов сверили с [документацией Microsoft о структуре WordprocessingML](https://learn.microsoft.com/en-us/office/open-xml/word/structure-of-a-wordprocessingml-document) (доступ2026-11-09):основной текст и дополнительные части отдельны. PDF-API/лимиты сверены с установленными исходниками pypdf6.21.4 (`_configuration.py`, `filters.py`, `PageObject.extract_text`) и функциональными fixtures; не заявляем проверку текущей интернет-версии. Два других открытия официальной справки завершились сетевым сбоем и не учитываются как прочитанные источники.
