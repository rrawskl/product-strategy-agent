# Контракт метрики v1 — НЕ УТВЕРЖДЁН

Шаблон для сервиса с повторяющимся полезным действием; скопировать в конкретный проект и адаптировать. Если фактический продукт другой, руководитель сначала определяет полезное действие, затем контракт пересматривается. Открытие приложения и push не являются полезным действием.

## Однозначное определение
- Единица: устойчивый обезличенный account_id; один аккаунт во всех устройствах. Гостевые пользователи без устойчивого ID исключаются и считаются отдельно. Слияния ID должны быть разрешены до расчёта по версии таблицы соответствий.
- Когорта: все новые внешние аккаунты с первой успешной регистрацией за календарную неделю (понедельник 00:00 — следующий понедельник 00:00 Europe/Moscow). Не ограничивать знаменатель активировавшимися пользователями.
- t0: время первой регистрации аккаунта за всю доступную историю. Если полной истории нет, статус «новый» недоказуем, такую выгрузку нельзя использовать для этой метрики.
- Возврат: хотя бы одно серверно подтверждённое успешное `task_completed` в интервале [t0+28×24ч, t0+35×24ч). Дубликаты по event_id удаляются; несколько действий одного аккаунта дают один возврат. Действия на границе 35 суток исключаются. Точное время UTC хранится с offset; недели отображаются в МСК.
- D28–34 retention = число вернувшихся / число включённых аккаунтов. Название не сокращать до неоднозначного D30.
- Знаменатель: все подходящие зарегистрированные аккаунты, включая удалившие аккаунт и не активировавшиеся; никаких исключений по поведению после t0. Согласовать допустимость обезличенного учёта удаления и правовые ограничения; при невозможности дать оценку смещения.
- Исключения до расчёта: сотрудники, QA и боты по заранее сохранённому списку/правилу, технические дубли аккаунтов. Правила одинаковы во всех когортах; причины и количества исключений сохраняются.
- Окно полноты: W = watermark, до которого подтверждена полная загрузка всех нужных событий, а не максимальная встреченная дата. Аккаунт зрелый только при t0+35 суток <= W. Основное сравнение недель — только полностью зрелые недельные когорты; незрелые показывать отдельно без оценки удержания. Не считать отсутствие события в неполной выгрузке оттоком.
- Сегменты: платформа, канал привлечения, версия и тип потребности, известные на t0; «неизвестно» — отдельная группа. Не выбирать сегмент по будущему возврату. Малые группы показывать с n и интервалом неопределённости, без утверждений о причине.

## Воспроизведение после утверждения
Зафиксировать hash выгрузки, W, версию схемы, словарь событий, правила ID и исключений. Проверить схему/типы/времена/полноту; дедупликация event_id с несовпадающим содержимым блокирует расчёт до разбора. Выделить t0 по истории, применить исключения, недели и зрелость. Сделать LEFT JOIN событий по account_id с заданными границами; COUNT DISTINCT вернувшихся / COUNT DISTINCT знаменателя. Сохранить числители, знаменатели, исключения, незрелые когорты и сегменты. Показать 95% интервал Wilson для долей; отличия когорт не считать причинным эффектом.

## Нужные материалы
1. Синтетическая событийная выгрузка (или разрешённая собственная обезличенная): event_id, account_id, event_name, event_time с зоной, success, schema_version; таблица регистрации и признаков на t0.
2. Словарь и история схемы, правила доставки, watermark, интервалы сбоев, правила ботов/QA и слияний ID, достаточная история регистраций.
3. Интервью/обращения с согласием и обезличиванием, привязанные к шагу пути и периоду; сейчас отсутствуют.

Агрегированная квартальная таблица не восстанавливает такой контракт. Согласовать: событие, недельные когорты, новые аккаунты и окно D28–34; указать изменения, если предложение не подходит.
